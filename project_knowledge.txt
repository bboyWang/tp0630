一、项目概述与目标
======================================================================

  项目目标: 利用少量标注样本 + 主动学习，对青藏高原湿地类型进行高精度
  语义分割。参考 Niu et al. 2025 ESSD 方法论，但适配为 JSON 多边形
  标注格式（而非 GeoTIFF 栅格标签）。

  分类任务: 3 类语义分割
    - 0: 湿地 (Wetland)
    - 1: 水体 (Water Body)
    - 2: 湖泊 (Lake)
    - -1: 忽略 (未标注的背景像素)

  核心挑战:
    - 512×512 大尺寸图像，但 GPU 显存仅 4GB
    - 多边形标注稀疏（仅正例，无负例背景标注）
    - 标注成本高，需主动学习最大化标注效率

  工作流程:
    人工标注 → 监督训练 → Margin Sampling → 挑30个最不确定样本
    → 人工标注新样本 → 加入训练集 → 下一轮训练 → 循环

三、模型架构
======================================================================

  3.1 U-Net 结构
    轻量级 U-Net，为 RTX 3050 4GB 优化:
      - 输入: 26 通道 (遥感波段)
      - 输出: 3 通道 (湿地/水体/湖泊)
      - 基础通道数: base_ch = 32
      - 总参数量: 3,307,907

    编码器: 26→32→64→128→256 (4层下采样, maxpool)
    瓶颈:   256→256 (双卷积)
    解码器: 256→128→64→32→3 (4层上采样, ConvTranspose2d + skip connection)
    最终输出: bilinear 上采样回输入尺寸

    每层: Conv3×3 → BN → ReLU → Conv3×3 → BN → ReLU
    编码器第2-4层 + 瓶颈层: Dropout2d(0.1)
    权重初始化: Kaiming Normal

  3.2 损失函数
    - CrossEntropyLoss(ignore_index=-1)
    - 仅计算标注像素的 loss，忽略未标注区域
    - 未使用 Dice Loss（与 AMP 混合精度冲突，inplace 操作问题）

  3.3 评估指标
    - OA (Overall Accuracy): 标注像素的总体准确率
    - mIoU (mean Intersection over Union): 3类的平均 IoU
    - 注意: 由于仅正例标注，OA 只计算标注区域的像素匹配率

四、训练策略与核心技术
======================================================================

  4.1 四象限策略 (Quadrant Strategy)
    这是本项目最重要的技术创新点。

    问题: 512×512 原始图像太大，随机裁剪 256×256 会丢失 75% 信息。
    解决: 将每个 512×512 样本固定切分为 4 个不重叠的 256×256 象限:
      - 象限 0: 左上 (Top-Left)
      - 象限 1: 右上 (Top-Right)
      - 象限 2: 左下 (Bottom-Left)
      - 象限 3: 右下 (Bottom-Right)

    训练模式 (quadrant_mode=True):
      - 180 基础样本 → 720 四象限训练样本
      - 每个象限独立训练，配合随机数据增强（翻转）

    验证/测试模式 (quadrant_mode=False):
      - 使用 256×256 中心裁剪 (Center Crop)
      - 确保评估一致性，不引入象限偏差

    效果: Val OA 从 ~60% (随机裁剪) 提升到 ~90% (四象限)

  4.2 数据增强
    - 训练时: 随机水平翻转 (p=0.5) + 随机垂直翻转 (p=0.5)
    - 验证时: 不增强

  4.3 归一化
    Per-chip Min-Max 归一化（逐样本独立归一化）:
      for each band: x = (x - x.min()) / (x.max() - x.min())
    注意: Z-score 标准化不兼容（导致训练不收敛）

  4.4 优化器与调度器
    - 优化器: AdamW (lr=1e-3, weight_decay=1e-4)
    - 调度器: CosineAnnealingWarmRestarts (T_0=15, T_mult=2)
    - 梯度裁剪: max_norm=1.0

  4.5 混合精度训练 (AMP)
    - 启用: torch.cuda.amp.GradScaler + autocast
    - 原因: RTX 3050 4GB 显存紧张，AMP 节省显存 + 加速
    - 代价: 无法使用 Dice Loss（与 autocast 的 inplace 不兼容）

  4.6 训练超参数
    - Batch size: 2 (显存限制)
    - Epochs: 60 (max), Early Stop patience: 15
    - 输入尺寸: 256×256
    - 输出尺寸: 256×256

  4.7 数据集划分 (v8)
    严格遵循论文的 8:2 比例:
    - Test:  30 个人类标注样本 (固定，从不在训练中出现)
    - Val:   48 个人类标注样本 (固定，用于早停和模型选择)
    - Train: 剩余 118 个人类标注 → 472 四象限训练样本
    - Pool:  1308 未标注样本 (用于主动学习采样)

    关键改进 (v7→v8):
      v7: Test = 随机 300 个样本 (含~276 弱标签，无有效像素 → OA 虚高)
      v8: Test = 固定 30 个人类标注样本 (全部有有效标注像素)

六、主动学习流程
======================================================================

  6.1 采样策略: Margin Sampling
    - 原理: 选择模型预测最不确定的样本
    - 计算: margin = 1.0 - (top1_prob - top2_prob)
      margin 越大 → 模型越不确定 → 标注价值越高
    - 实现: 对每个 pool 样本，分别推理 4 个象限，取 margin 平均值
    - 排序: margin 降序，选 Top-30

  6.2 工作流
    Step 1: 监督训练 (train_active.py)
            → 保存 best.pth 到 checkpoints_vX\
            → 自动运行 Margin Sampling
            → 输出 uncertain_vX.txt

    Step 2: 人工标注 Top-30 不确定样本
            → 在 LabelMe/EISeg 中标注多边形
            → 将样本名加入 ready.txt 新批次

    Step 3: 下一轮训练
            → 更新 train_active.py (vX → vX+1)
            → 修改 save_dir, out_file, val_n 等参数
            → 重新训练

九、关键经验教训
======================================================================

  9.1 数据层面
    - 四象限策略是突破性改进: 512→4×256 比随机裁剪好得多
    - Per-chip Min-Max 归一化 > Z-score (后者导致不收敛)
    - 稀疏正例标注(无背景)限制了模型能力:
      → 模型不会学习"什么不是湿地"
      → mIoU 偏低是预期内的
      → 考虑添加背景类标注或使用负采样

  9.2 训练层面
    - AMP 混合精度适合 4GB 显卡，但限制 loss 选择
    - CosineAnnealingWarmRestarts 效果不错
    - CE Loss 简单但有效，Dice Loss 与 AMP 不兼容
    - OA 波动大: 需要更大 batch (但显存不够)或梯度累积
    - 早停 patience=15 合理，防止过拟合

  9.3 主动学习层面
    - Margin Sampling 简单高效，适合多分类
    - 四象限平均 margin 比单中心裁剪更鲁棒
    - 每轮 30 个样本是合理的标注负担
    - 新标注只加入训练集，Val/Test 保持固定

  9.4 工程层面
    - 笔记本 SSH 训练: 进程不随 SSH 断开而存活
    - 建议用 screen/tmux 但 Windows 不支持
    - 输出重定向到文件时 Python 可能缓冲，用 -u 标志
    - checkpoint 保存在本地，不怕训练中断

  9.5 数据集划分 (v8 重要修正)
    - Test 集必须仅来自人类标注 → v7 的 300 随机 test 是无意义的
    - Val 集需要足够大 (≥48) → v7 的 20 导致 OA 波动 5%-90%
    - 参考论文: Niu et al. 2025 ESSD 使用 8:2 训练:验证比例
